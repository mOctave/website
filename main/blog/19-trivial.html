Trivial

16 June 2026

Shortly after publishing Bitwise, I started working on another project that I've been meaning to get around to for a little while: a competitve trivia game that lets players challenge each other to questions of their own choosing that I dubbed Trivial. For the last couple of weeks, Trivial has been up as a public beta, and you can play it now at trivial.moctave.net.

The project's still a little rough around the edges. There's content missing, there are some very simple exploits you can use to manipulate your duels rating, and beta testing revealed inexplicable intermittent lag that seems to be an issue with the server in my basement rather than the code itself. However, it is available, it is playable, and it is probably the most complex web development project I've attempted yet.

The basic framework of the project isn't too different from Flagrank: there's a NodeJS Express backend (albeit with a much better structure than Flagrank and separate routes, controllers, and services), an EJS frontend that is hacked together but generally functions, and a whole bunch of SVGs tossed in for good measure. However, the first big change is that this time around I actually used a proper database.

While working on Paper Cuts, I was introduced to MongoDB for the first real time. I had heard of it before, but that project really let me see how useful it was. If, like me, the last time you touched SQL was five years ago and it resulted in the destruction of your sanity and/or database, MongoDB and Mongoose is a much easier way to get all the protections of a database while only having to remember a few method calls. Best of all, the whole thing is basically just JSON which means it should even be compatible with Flagrank if I ever decide to update it.

Of course, there were lots of other challenges with this project. For one, its scope was way bigger than Flagrank. Instead of a (not-so) glorified voting system, I had to build:

  • the game,
  • the system to host/join/be automatically paired up for games,
  • the system to create and manage decks and cards, and of course
  • sEcUrItY fEaTuReS

If you think you can't trust anyone who types the words "sEcUrItY fEaTuReS" like that to put together a safe website and not sell your data to Cambridge Analytica, welllll... you have a point. Please don't use your nuclear launch codes as your username and password. However, by using JSON web tokens, proper server-side hashing algorithms, and cookies, I've managed to scrape together an authentication system that lets you use the website with a single sign-on per session whilst not bleeding your data all over the place.

Seriously though, no nuclear launch codes. Just because I learned a lot about authentication doing this project doesn't mean you should trust my database-on-a-server-in-my-basement security setup.

Lastly, I learned a huge amount about how Javascript (and by extension NodeJS) works. Between dabbling with asynchronous functions, correctly managing imports and routes, and learning that there are better ways than 

foo.innerHTML += `
${Content of the div}
`
to manipulate page content, this project's codebase is a lot messier than many of my recent projects but will also enable me to make much less of a mess with my newfound knowledge in the future.

If you'd like to play Trivial, you can register for an account (just remember no nuclear secrets) by clicking here. There are still lots of minor bugs and I'm planning plenty more features, so if you'd like to watch my progress or maybe even help make things better yourself you can find the source code on GitHub.
