Uptime, Downtime, SSD Failure

10 July 2026

You may have noticed (or not) that this website was down recently. Apparently the server suffered a catastrophic SSD failure sometime on July 1. The good news: there was already a second SSD ready to be put to use. The bad news: the server had previously decided not to back up for six months straight.

Thankfully, because I keep the majority of my website under source control beyond a couple of config files and my new Trivial database, it was relatively easy to just use git clone and/or git pull to get most of the important data back, and I was able to manually restore the config files to proper working order. In the end, the only notable casualty is the Trivial database, which needed to be cleaned up anyways but probably didn't deserve complete annihilation? Oh well.

So, how am I going to prevent my website going down for a week in the future? I'm glad you asked.

Firstly, and most importantly, I'm now monitoring the main site, Flagrank, and Trivial with UptimeRobot. This should allow me to realize if my site is down and respond within ten minutes instead of ten days.

Additionally, it's served as a good reminder to me that I really should start looking into how to do backups for MongoDB databases, improve Flagrank to use an actual database and npm start, and get MongoDB and my two Express servers running on the server as services. But, naturally, just because I have that reminder doesn't mean I'll do anything about it.
